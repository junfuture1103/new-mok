# 한 수 0.1 · 검증 기록

2026-09-08. 실험용 추상전략 게임 세 편을 구현하고 규칙·자동 대전·실제 브라우저 조작을 검증했습니다. 사람 플레이테스터의 재미 평가는 아직 수집하지 않았습니다.

## 최종 검증

- 규칙 테스트 15개 통과. 이 중 상태 불변조건 검사는 세 게임 각 50판, 총 150판을 끝까지 실행합니다.
- TypeScript 타입 검사 통과.
- 배포용 정적 빌드 성공. 게임은 정적 파일만 사용합니다.
- 브라우저 조작 테스트는 Microsoft Edge에서 정적 빌드를 대상으로 수행했습니다. 밀기, 구멍 생성, 점프와 패 전달, AI 응수, 무르기, 대기 중 새 대국, 세 게임 완주·승패 잠금·재시작, 모바일 폭과 키보드를 검사합니다.
- 1440px 데스크톱과 390px 모바일 화면을 확인했습니다. 모바일에서 가로 넘침이 없고, 브라우저 오류가 관찰되지 않았습니다.
- 지원 브라우저 전용 WebMCP는 검증 브라우저에 API가 없어 실제 등록 및 호출을 검증하지 못했습니다. 일반 플레이에는 영향을 주지 않습니다.

## 최종 규칙의 자동 대전 360판

각 게임당 무작위 대 무작위 60판, 신중 대 신중 20판, 신중 대 가볍게 20판, 가볍게 대 신중 20판. 난수는 `seed * 179 + 41`로 재현합니다. 모든 경기가 승패 또는 명시한 무승부 규칙으로 종료했습니다.

| 게임 | 신중 AI끼리 흑승 / 백승 / 무승부 | 평균 수 | 신중 AI vs 가볍게 AI: 신중 AI 승리 (색 교대 합산) |
|---|---:|---:|---:|
| 파문 | 9 / 11 / 0 | 23.3 | 32 / 40 |
| 침식 | 10 / 10 / 0 | 20.5 | 37 / 40 |
| 유산 | 14 / 6 / 0 | 17.1 | 39 / 40 |

수는 한 사람이 행동한 횟수(half-move)입니다. 전체 결과, 종료 이유 및 대표 기보는 `simulation.json`에 있습니다. 최종 유산의 무작위 대전 60판 중 1판은 160수 제한으로 종료했습니다.

## 테스트를 보고 변경한 것

유산 초기 배분(흑: 걸음·빗길·도약)은 동일 AI끼리 20판 모두 흑이 17수에 이겼습니다. 시작 패의 10가지 배분을 각각 12판 비교하고(`opening-experiment.json`), 후보 네 가지를 다른 난수 범위 1001~1100에서 각 100판 추가 비교했습니다(`opening-validation.json`).

최종 배분은 흑: 도약·날개·갈고리 / 백: 걸음·빗길입니다. 추가 비교 100판은 흑 44승·백 56승·무승부 0판이었고 평균 19수였습니다. 최종 정기 시뮬레이션의 다른 난수 20판에서는 흑 14승·백 6승이었습니다. 두 표본을 합치면 120판에서 흑 58승·백 62승입니다.

이 결과는 특정한 얕은 탐색 AI와 시작 상태에 대한 관찰입니다. 후보 선택에 사용한 데이터이므로 독립적인 공정성 인증이 아니며, 작은 표본에서는 승률이 크게 달라집니다. 규칙이 해결되었다거나 최적 플레이에서 균형이 맞는다는 뜻이 아닙니다.

## 다음 사람 테스트에서 확인할 것

1. 파문의 밀림을 2~3턴 안에 예측하는지, 상대 돌의 받침을 의식적으로 쓰는지.
2. 침식의 영구적 구멍 때문에 선택을 후회하고 재도전을 원하는지.
3. 유산에서 넘길 패까지 고려하는지, 현재 카드 이름과 작은 도식만으로 규칙을 이해하는지.
4. 세 게임 각각 선후공을 바꾼 10판 후, 다시 두고 싶은 게임과 이유를 기록하기.

원형 게임으로서의 독창성 비교, 숙련자 밸런스, 장기 전략 다양성은 아직 검증하지 않았습니다. 기존 게임 파일은 별도 상위 프로젝트에 남아 있습니다.

## 디자인 개정

2026-09-08. 큰 소개 문구와 영문 장식, 둥근 카드형 메뉴를 제거했습니다. 게임 이름만 있는 상단 메뉴, 명조 제목, 판 바깥의 좌표, 나무색·회색·적갈색 판으로 세 게임을 구분했습니다. 조작과 규칙은 별도 카드 테두리 없이 정렬했습니다.

게임 규칙과 AI는 변경하지 않았습니다. TypeScript 검사와 정적 빌드가 성공했고, 기존 브라우저 테스트 9개(세 게임 완주·모바일·키보드 포함)가 모두 다시 통과했습니다. 내장 브라우저에서 화면 배치를 확인했습니다.

이때 사용 가능한 네이티브 WebMCP 연결에서 `read_game`, `start_game`, `play_move`의 등록과 합법적 이동을 확인했습니다. 잘못된 게임 이름과 불법 이동은 거절되었고, 거절 전후 상태가 동일했습니다. 초기 검증 때 남았던 WebMCP 연결 확인의 한계를 해소했습니다.
