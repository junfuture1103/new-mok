# 보안·사용성 점검 · 2026-09-16

GitHub Pages의 한 수와 별도 D1 온라인 API를 대상으로 소스 검토, 실제 브라우저 조작, 비정상 요청, 동시 요청, 접근성 자동 검사를 수행했습니다. 대상 게임은 파문·침식·유산입니다. 아래 결과는 검사한 조건에서의 결과이며 모든 환경에서 무결점이라는 뜻은 아닙니다.

## 발견하고 수정한 문제

| 항목 | 문제와 영향 | 수정 |
| --- | --- | --- |
| 잘못된 게임 값 | 문자열 대신 `["ripple"]`을 보내도 방이 만들어져 이후 처리에 사용할 잘못된 상태가 저장됨 | 게임을 문자열 세 종류로 엄격히 제한, 착수 필드·요청 UUID·JSON 형식과 크기도 검사 |
| 상대 착수 중 나가기 | 확인창을 열고 있는 동안 상대가 두면 버전 충돌로 다시 눌러야 했음 | 나가기·기권은 같은 대국 회차에서 처리하고, 이전 회차의 요청은 거절 |
| 저장소 일부 차단 | 닉네임 저장소 접근 실패가 탭에 남은 정상 입장 정보의 복원까지 막음 | 닉네임 설정과 참가자 정보 읽기를 분리하고 저장 데이터 검증 |
| 입장 응답 유실 | 서버에서는 입장했는데 응답만 유실된 뒤 닉네임을 바꿔 재시도하면 자리를 잃을 수 있음 | 같은 방 입장 재시도에 같은 참가자 토큰 사용 |
| 연결 단절·만료 | 대기실로 돌아오며 입장 정보를 잃거나 만료 방에서 계속 재연결을 표시 | 자리 보관 후 ‘이전 방 이어두기’, 만료·권한 오류의 명확한 종료 안내 |
| 불필요한 요청 | 닫힌 방에서도 상태 확인을 반복 | 닫힌 상태를 확인하면 주기적 요청 종료 |
| 확인창 키보드 조작 | 확인창 밖으로 포커스가 빠지거나 취소 방법이 불명확 | 모달 dialog, 취소 버튼 우선 포커스, Tab/Shift+Tab 순환, Escape 닫기 |
| 글자 가독성 | 작은 안내 글자의 대비가 일부 화면에서 2.76–4.35:1로 부족 | 종이 배경과 기존 디자인을 유지하며 글자와 좌표 색을 진하게 조정 |
| 보조기기·입력 | 유산 중심 말의 의미가 읽히지 않음, 닉네임 입력 후 버튼까지 이동 필요 | 중심 말 접근성 이름, 닉네임에서 Enter 입장/생성, 한글 조합 중 Enter 보호 |

## 보안 보완

- 서버가 참가자, 차례, 합법적인 수, 판 버전과 대국 회차를 검증합니다. 동시 입장·착수에는 SQL 버전 비교를 사용하고 재전송은 요청 ID로 중복 처리하지 않습니다.
- SQL 값은 바인딩합니다. 닉네임은 일반 텍스트로 렌더링하며 HTML·제어문자를 거절합니다. 응답·초대 링크에 참가자 토큰이나 그 해시를 넣지 않습니다.
- 생성은 IP당 시간 구간 1시간에 12회, 입장 시도는 IP당 1분에 30회, 인증된 변경 요청은 방/참가자당 1분에 120회로 제한합니다. 제한 기록은 원본 IP 대신 시간 구간 해시를 사용하며 거절된 기록의 카운트를 계속 늘리지 않습니다.
- 허용된 웹 출처만 교차 출처 API를 호출할 수 있습니다. 본문은 실제 스트림 크기까지 4KB로 제한합니다.
- 정적 HTML에 CSP를 넣었습니다. 빌드된 인라인 스크립트만 SHA-256 해시로 허용하고 임의 인라인 스크립트 실행을 차단합니다. 폰트·스크립트는 자체 호스팅하며 API 연결 출처도 제한합니다. React 스타일 처리 때문에 인라인 스타일은 허용합니다.
- HTML에 `no-referrer`, API와 Worker 응답에 MIME 추측 방지·프레임 차단 등 응답 헤더를 적용했습니다.
- 재대국 시 흑백 자리와 접속 상태 시각을 함께 교환합니다.

## 의존성

초기 `npm audit`의 경고 14건(높음 8, 보통 6)을 확인했습니다. React 계열 19.2.8, Vite 8.0.16과 관련 간접 의존성의 수정 버전을 적용하고 쓰지 않는 Wrangler/Cloudflare Vite 플러그인을 제거했습니다. 최종 설치 목록의 **`npm audit`: 알려진 취약점 0건**입니다. 이는 코드 자체에 대한 침투 테스트 인증이나 향후 취약점 부재를 뜻하지 않습니다.

React Server Functions 및 개발 서버 경고도 포함되어 있었습니다. 운영 API는 별도 Worker이며 해당 개발 서버나 React Server Functions를 외부에 노출하는 구조는 아닙니다. 빌드 경로까지 최신 보안 수정으로 정리했습니다.

- [React 공식 보안 공지](https://github.com/react/react/security/advisories/GHSA-wx67-qw84-cm4g)
- [Vite 공식 보안 공지](https://github.com/vitejs/vite/security/advisories/GHSA-fx2h-pf6j-xcff)

## 검증 범위

- 규칙·복원·서버 검사 33개 통과. 150판 무작위 완주 상태 검증 포함.
- TypeScript 타입 검사 통과, 배포 빌드 성공, Drizzle 스키마 변경 없음.
- Edge: 브라우저 검사 32개 모두 통과. 마우스/터치 한 번 조작, 느린 초기 로딩, 로컬 대국 복원, 온라인 2인 동기화, 세 게임 완주, 재대국·재접속 및 아래 복구 검사를 포함합니다.
- Firefox: 온라인 복구·확인창·CSP·접근성 6개와 기존 게임 조작·완주 9개, 총 15개 통과. Firefox가 차단하는 기존 로컬 포트 4190을 4173으로 변경했습니다. 운영 URL은 변경하지 않습니다.
- 두 브라우저에서 대기실·390px 대국방·확인창·홈 화면에 axe의 WCAG 2/2.1/2.2 A·AA 규칙을 실행하여 자동 감지된 위반 0건. 키보드 순환·Escape·보드 방향키도 별도 확인했습니다.
- 저장소 접근 실패, 오프라인 진입/복구, 입장 응답만 유실, 만료 방, 동시 입장, 중복 착수, 잘못된 토큰, 허용하지 않은 출처, 이전 회차의 나가기/기권, 비정상 값, 요청 제한을 검증했습니다.
- 실제 브라우저 화면을 확인했고 로컬 Pretendard 및 라이선스를 유지했습니다.

운영 확인 결과는 배포 후 별도 결과 안내에 기록합니다. 회귀 검사는 `tests/online.test.ts`, `tests/browser/online-audit.spec.ts` 및 기존 브라우저 검사에 남겼습니다.

## 남아 있는 범위와 운영 조건

- 실제 iOS Safari 기기, 서로 다른 통신사의 물리적 네트워크, 장시간 대량 동접·분산 공격은 검사하지 않았습니다. 요청 제한은 완전한 DDoS 방어를 보장하지 않으며 인증된 상태 조회는 주기적으로 계속 허용합니다.
- 자동 접근성 검사 통과는 전체 WCAG 준수 인증이 아닙니다. 실제 스크린리더 사용자 검사는 별도로 필요합니다.
- 초대 링크를 아는 사람은 빈 두 번째 자리에 입장할 수 있습니다. 닉네임은 신원 인증이 아닙니다. 탭의 참가자 정보를 완전히 삭제하거나 잃으면 계정 기반 복구는 할 수 없습니다.
- 방은 생성 후 24시간 유지되고 상대 상태 반영은 일반적으로 약 1.2초 간격입니다. 의도적인 오프라인에는 자동 패배를 적용하지 않습니다.
- GitHub Pages는 사용자 정의 HTTP 보안 헤더 설정이 제한됩니다. HTML CSP와 referrer 설정은 적용되지만, 프레임 임베딩을 막는 `frame-ancestors`는 메타 태그로 지원되지 않습니다. API/Worker에는 해당 헤더를 적용했습니다.
- 흑 선공 규칙과 게임 밸런스는 이번 오류·보안 점검에서 변경하지 않았습니다.
